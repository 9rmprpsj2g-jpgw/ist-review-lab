# Proposed audit storage — awaiting approval

Do not generate census audits until this storage proposal and the compute estimate are approved. No storage routing, ignore rule or archive upload has been activated by this proposal.

Proposed directory: `audit_store/<generation_id>/`, with repository-root `.gitignore` rule `/audit_store/`. Use a generation identifier combining UTC launch date and the resolved-config SHA-256 prefix; never reuse a generation directory. Files are uncompressed schema-3 JSON, one per topic/seed/policy/budget, written to a temporary sibling, flushed/fsynced/closed, then atomically renamed. No audits are committed to git. The output runner needs a separate audit-directory option before the approved run; its current output-directory/audits destination is not yet this proposed route.

Commit `audit_manifests/<generation_id>.json` after successful completion. Top-level metadata: generation ID, audit schema version, code commit, resolved config and SHA-256, source-data and canonical feature-matrix digest (including shape, dtypes and row/column ordering), environment/library versions, seeds and RNG derivation identifier, expected grid, completed/failed/missing counts, and external archive location/version. Each entry: relative filename, topic, seed, policy, budget, N, completed review count, rounds, fits, margin scope, byte size, SHA-256 of the exact file bytes, and validation status. Do not include a success entry for partial files. Commit a completion manifest only when its expected grid is reconciled. Keep any failure receipt explicit.

Distribute the audits separately as an immutable archive in an owner-selected durable object store or institutional repository; provider and retention remain undecided. An ignored local directory is not a backup. Retain the archive and a separately verified backup before deleting local files. If transport compression is used, provide archive checksum/size and retain the per-file checksums of decompressed JSON.

Third-party verification: obtain the manifest from its identified git commit and the archive separately; verify archive checksum if applicable, safely extract, compare each JSON file's exact byte length and SHA-256 against the manifest, check run metadata and expected-grid completeness, parse JSON and call src.audit.replay_row_order, then compare its output and cumulative round boundaries with row_order and batch_ends. Hashes establish agreement with committed bytes, not scientific correctness. Recomputing margins additionally requires the declared data/features, environment, ordered training labels/temporary negatives and actual fit parameters. No unauthenticated replacement manifest should be accepted as proof of the original archive.
